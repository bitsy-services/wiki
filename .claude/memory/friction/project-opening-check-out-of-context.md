2026-09-11, RoPE invariance page. Following `wiki-workflow.md` ("Show the
opening before writing the body"), the `## Part` paragraph was shown for
approval before drafting. After two rounds of confusion about what was being
asked, the user said: "I don't want to read something out of context. Use your
judgement. If I don't like it I will tell you."

Hypothesis: the rule was written after one incident (an opening that did not
parse and survived review) and reads as "stop for approval", but the user's
actual preference is to read the finished page, where the opening has its
context, and object then. A stop to approve a fragment costs a round-trip and
asks for a judgement the user cannot make well without the rest of the page.

**Why:** the rule and the user's stated preference now conflict; the user's
words are the more recent evidence.

**How to apply:** draft the whole page, run the gate and the reviewer, and
present the finished page. Put the opening where the user will see it first,
in context — do not stop for approval of a fragment. `wiki-workflow.md` still
says otherwise; changing it is a rules edit and needs the user's yes. Related:
[[global-name-the-blocker]].
